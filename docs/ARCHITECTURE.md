# ARCHITECTURE.md

## Stack

Next.js 16 (App Router, TypeScript) · PostgreSQL 16 · Kysely + pg ·
Auth.js v5 (Credentials, JWT sessions) · Zod · Tailwind v4 · shadcn/ui.

## Request flow

```
Browser
  -> proxy.ts (session cookie check only -- public: /login, /setup)
    -> (app)/layout.tsx (DB check: is setup complete? else -> /setup)
      -> page.tsx (Server Component -- fetches data with Kysely)
        -> *Client.tsx (Client Component -- interactivity, calls Server Actions)
          -> actions.ts (Server Action -- re-derives state from DB, never
            trusts the client, validates with Zod, writes with Kysely)
```

Every mutation re-checks authorization and business-rule state from the
database inside the Server Action itself. The UI disabling a button is a
convenience, never the actual guard -- see docs/BUSINESS_RULES.md and the
attendance integration tests for the specific case the spec asked to
verify (a direct mutation attempt while the teacher is marked absent is
rejected server-side, not just hidden from the form).

## Two non-obvious things worth knowing before changing code here

**CamelCasePlugin is load-bearing.** The SQL schema is snake_case; types.ts
is generated with `--camel-case`. Without `CamelCasePlugin` registered on
the Kysely instance, `.selectFrom("sessionCancellation")` sends that
literal (wrong) identifier to Postgres. This was a real bug caught only by
running the app, not by typecheck -- see docs/DATABASE.md.

**DATE columns are typed and returned as `string`, not `Date`.** `pg`
defaults to parsing SQL DATE as a JS Date object at UTC midnight, which
invites timezone-shift bugs for values that are pure calendar dates
(academic year bounds, holidays, session dates). client.ts overrides the
type parser; scripts/codegen-db-types.mjs re-patches the generated types
to match every time they're regenerated.

## RTL

Arabic bidi reorders space/dash-separated digit groups (phone numbers,
time ranges) inside RTL paragraph text -- "18:00 - 20:00" renders as
"20:00 - 18:00" unless isolated. components/Ltr.tsx wraps any such value
in dir="ltr". Apply it to every new phone number, time range, or similar
composite numeric string -- see docs/BUSINESS_RULES.md for the full list
of places this was already applied.
