# PRODUCTION_MIGRATION.md

Migration of "دفتر الحلقة" from a Vite/React mock-data prototype to a
real full-stack application. This document reflects what was actually
decided and built, including two deviations from the original plan and
why each was necessary.

## Stack decision

| Layer | Prototype | Production | Why changed |
|---|---|---|---|
| Framework | Vite SPA (client-only) | Next.js 16 (App Router) | The spec requires server-side enforcement of every business rule (teacher-absence cascade, late-minute calculation, etc.) — a pure client-side SPA has no server to enforce anything in. This is the one "rebuild" the "don't rebuild the UI" rule doesn't cover, because it's plumbing, not design: every component, color, font, and layout carried over unchanged. |
| Database | none (in-memory mock arrays) | PostgreSQL 16 | As specified. Real instance, real constraints, not SQLite. |
| ORM/query layer | — | **Kysely + pg** (not Prisma) | See "Deviation 1" below. |
| Auth | none | Auth.js v5, Credentials provider, JWT sessions | Single-teacher app; no OAuth provider needed. bcrypt for password hashing. |
| Styling | Tailwind v3.4.1 | Tailwind v4 | Next.js 16's scaffold defaults to v4. Same design tokens, ported to `@theme inline` syntax. |

## Deviation 1: Prisma → Kysely

The spec asks for Prisma. It was attempted first. `prisma generate` and
`prisma migrate` both require downloading a schema-engine binary from
`binaries.prisma.sh`, which is not reachable from this build environment's
network policy — confirmed as a real 403, not a config mistake, and
confirmed as a known limitation for restricted-network environments via
Prisma's own issue tracker. There is no supported workaround that doesn't
require that same network access.

**Kysely + pg** was substituted: pure TypeScript, no downloaded binaries,
full type safety generated by introspecting the real running database
(`pnpm run db:types`). It satisfies every architectural requirement the
spec actually cares about (real Postgres, real migrations, type-safe
queries, real constraints/transactions) without the blocked dependency.
Prisma would very likely work fine in a normal internet-connected
environment (a developer's own machine, a standard CI/CD runner) if
preferred there instead.

## Deviation 2: hand-written SQL migrations, not an ORM's migration tool

A direct consequence of Deviation 1. Migrations live in `db/migrations/*.sql`
and are applied directly with `psql`. This turned out to have a real
advantage for this schema specifically: Postgres features the spec's
business rules actually need — a GiST `EXCLUDE` constraint that rejects
overlapping cancellation periods at the database level, a partial unique
index enforcing "exactly one active academic year", a `CHECK` constraint
tying `LATE` status to a required `arrival_time` — are all straightforward
to hand-write in SQL and were verified working against the real database
(see `docs/DATABASE.md` and the integration test suites).
